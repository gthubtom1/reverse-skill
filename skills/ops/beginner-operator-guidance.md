# Beginner Operator Guidance Contract

Use [guided-operator-contract.md](guided-operator-contract.md) for the canonical card IDs, copyable options, scope composition, alias resolution and reporting rules. This file gives presentation guidance only; it does not create a second router, PRIMARY, case system, provider or GOAL engine.

The operator describes a desired result in ordinary language. Accept an already clear goal and existing authorization. The agent chooses tools and technical paths, and proceeds with bounded work in scope. A progress report is informational, not an approval request.

At a material milestone or blocker, briefly explain what was done, what is confirmed, what is unknown and what follows. Keep raw addresses, commands, YAML and implementation details in Evidence or an appendix. Do not require the user to understand REA, Ghidra, Frida, IAT, Static or Dynamic.

Only a genuine user decision gets options. Show 2–5 feasible result/scope/delivery choices with local A/B/C or numbered aliases and stable `GOAL-*`, `SCOPE-*`, `DELIVERY-*` IDs. Each option is a copyable plain-language sentence with its effect, expected outcome and recommendation. Resolve an alias against the latest offered set in the same case; do not infer scope from an unbound ID. Missing user-only materials require a concise input request, not a fabricated menu.

Example of a partial result:

```text
已经确认：主程序中的一个检查点已验证。
尚未完成：另外六个授权面，以及导出功能的回归验证。
下一步：继续核对剩余组件并检查相关功能；当前是 1/7，不能称为整体完成。
```

If execution is outside the current scope, explain the concrete effect and offer the scoped alternatives from the canonical contract. If execution was already authorized, choose the smallest relevant experiment and continue. Provider failure, multiple technical routes, a stage transition, fact-checking or subagent delegation does not create a user decision.

Restore settled goals and answers from the conversation and original case. Ask a missing user-only fact once and continue independent work while waiting. Reopen only a decision that new evidence invalidates. Do not ask the user to reconfirm every command or every stage. A source-reconstruction proposal must preserve its current feasibility, unknowns, success criteria and equivalence level; it is not a promise to recover the original author's source.
