# JS：最小补环境与签名输入的字节边界

本篇延伸 [最小补环境规则](env-patching.md)，重点是补丁引入的语义偏差与签名输入首次分歧。引入批次：首批全领域增补；引入版本待独立 release PR 分配。文档核对不代表已复现任何站点签名。

## DK-JS-01：Proxy 能记录访问，也会改变程序行为

**现象→判定：** 添加“万能对象”后异常消失，但输出仍错，不能判定环境已补齐。ECMAScript 的 Proxy `[[Get]]` 有不变量：目标自身不可配置且不可写的数据属性，trap 必须返回同值；不可配置且没有 getter 的访问器属性只能得到 undefined。违反会抛出 TypeError。

**方法：** 先在原运行环境记录缺失访问的调用点、属性描述符、返回类型和异常；本地只补这一因果单元。优先保留原型与描述符，再比较相同输入下首次分歧的位置及输出。若用 Proxy 观察，应同时记录它自身造成的额外访问和异常，设置可撤回的单项补丁，避免递归兜底吞掉真实依赖。

**版本/边界/反例：** 依据当前 ECMAScript 在线规范；具体引擎版本须随复现记录。返回空函数无法自动满足宿主对象的品牌检查或内部槽要求。把所有未知属性都返回函数，会把布尔判断、类型判断和分支一起改掉；“脚本不再报错”只是异常减少，不是行为一致。

**验证状态：未验证。** 原文来源：[S10：Proxy 的 Get 算法与不变量](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-proxy-object-internal-methods-and-internal-slots-get-p-receiver)。

## DK-JS-02：canonicalization 必须有协议依据

**现象→判定：** 对象内容看似相同而签名不同，应比较实际参与计算的字节，而不是先换散列算法。JCS 规定属性名按原始字符串的 UTF-16 码元排序，保留数组顺序；字符串须保持原样，不能擅自做 Unicode 规范化。它也不是所有接口默认使用的 JSON 格式。

**方法：** 在序列化前、编码后、摘要前分别记录长度和字节，定位首次差异；准备空格、加号、非 BMP 字符、重复查询键与数组顺序的对照。若接口明确采用 RFC 8785 才应用其规则，否则按观测恢复。表单编码与 JSON 分开：URLSearchParams 的表单序列化把空格变成 `+`，字面加号需另行编码，不能混用一般查询字符串处理。

**版本/边界/反例：** RFC 8785 是信息性 RFC，WHATWG URL 是动态标准，本批只核当前原文。JCS 属性排序不是按 UTF-8 字节排序；擅自排序数组、做 NFC 或先解码再重编码，都可能改变签名输入。即使标准测试向量匹配，仍需用目标协议的已知接受与拒绝样例检验。

**验证状态：未验证。** 原文来源：[S11：RFC 8785 §3.2](https://www.rfc-editor.org/rfc/rfc8785.html#section-3.2)、[S12：URLSearchParams 序列化](https://url.spec.whatwg.org/#interface-urlsearchparams)。
