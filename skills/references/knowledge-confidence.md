# 知识可信等级 / Knowledge Confidence

本仓使用两条独立轴：**方法评审**与**本方/目标验证**。它们不互相替代。

## 方法评审等级

| 等级 | 进入条件 | 可表达的结论 |
|---|---|---|
| 来源支持 | 官方规范、官方文档、成熟项目源码或可追溯公开案例直接支持；正文与条件已核 | 该机制/方法有可靠出处；仍需遵守出处的平台和版本范围 |
| 交叉核对 | 两个或以上独立可靠来源支持同一机制，且术语、条件、反例一致 | 方法在一般层面较可信；具体目标仍需自己的证据 |
| 方法可信 | 已完成来源核对、内部代码/公式/协议逻辑检查和反例审阅，没有已知矛盾 | 可作为正式方法纳入基线；不等于已经在本方目标运行 |
| 来源存疑 | 只有标题/摘要/二手转述，来源不可达，版本不明或正文不支持结论 | 只能作为待研究线索，不能作为默认方法推荐 |
| 待修订 | 已发现错误、过度泛化、条件缺失或与独立来源冲突 | 保留原记录和失败原因，修订前不作为可靠方法使用 |

“交叉核对”是方法评审，不要求每个来源都被本方实际运行；来源的可访问性、正文支持和技术正确性分别记录。

## 本方验证等级

| 等级 | 含义 |
|---|---|
| 未复现 | 没有在本方 fixture、练习题或目标上跑过；可能已有来源支持或方法可信评审 |
| 本方复现 | 在固定输入、平台、工具和输出判据下跑过合成 fixture 或公开练习题 |
| 目标验证 | 在明确目标、版本、环境和范围内完成了对应闭环 |

当前公开知识条目常见组合是“方法可信／本方未复现”。这表示它有依据，尚未在本方目标上跑过。它不等于“无效”，也不等于“对所有目标有效”。

## 评审要求

每条方法至少说明：

- 来源性质和原文链接；
- 适用平台、架构、版本和前置条件；
- 现象、判定、方法和失败/反例；
- 方法评审等级；
- 本方验证等级；
- 哪些结论仍依赖具体目标或设备。

公开文章中作者声称的成功、工具安装成功、HTTP 200、进程退出码0和文件可反编译，都不能单独升级本方验证等级。来源足够可靠时可以纳入正式基线，但必须保留限定条件。

## 评审结果写法

推荐格式：

```markdown
**方法评审：交叉核对。** 来源正文已核，条件与反例已检查。
**本方状态：未复现。** 尚未在本方 fixture/目标上运行。
```

来源存疑或待修订时，写明具体原因和恢复检查；不删除旧经验，不用新文章静默覆盖冲突。

本契约属于 reverse-skill 的知识维护约定，不增加新的路由器、数据库或运行时。安装仓库只负责定位该说明，官方 REA/Spec Kit 保持原版。
