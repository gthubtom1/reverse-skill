# iOS：元数据缺口与动态观察的运行前提

本篇补充 [既有 iOS 指南](ios-reverse-guide.md) 的结论边界，不把提取到 IPA、列出方法和成功运行混为一项能力。引入批次：首批全领域增补；引入版本待独立 release PR 分配。下述方案尚未在本方设备复现。

## DK-IOS-01：方法列表不等于可调用行为全集

**现象→判定：** 导出的类中没有目标 selector，不能立即判定功能不存在。Apple 的运行时头文件明确：`class_copyMethodList` 不遍历父类；查类方法需针对元类。静态头文件恢复也不能证明消息派发时最终使用哪份实现。

**方法：** 在已获授权且可观察的进程中，记录 image、类、selector、方法类型及枚举时机；分别检查本类、父类和元类。对命中项再取得类型编码与实现地址，把运行时地址关联到所加载模块。对未命中项保留“本次枚举未见”，用实际业务调用点验证假设，避免仅据字符串给功能命名。

**版本/边界/反例：** 以 Apple objc4 当前公开头文件为依据，具体系统仍须核运行时接口。纯 Swift 路径未必暴露为 Objective-C 方法；元数据能恢复接口线索，不能恢复原始源码，也不能把继承方法的缺席解释成混淆。后续加载或运行时替换同样会使一次快照失效。

**方法评审：来源支持（来源正文已核，已检查适用条件与反例；未做本方目标实测）。** **本方状态：未复现。** 原文来源：[S07：Apple runtime.h 的方法枚举与父类查找注释](https://raw.githubusercontent.com/apple-oss-distributions/objc4/main/runtime/runtime.h)。

## DK-IOS-02：加密状态、签名和可调试性分别核验

**现象→判定：** IPA 能解包但反汇编异常或无法附加，不能统一归因于“反调试”。Mach-O 加密命令描述文件加密区间；架构切片、代码签名、设备运行资格、动态插桩前提是不同问题。FAT 只是多架构容器，不是加密格式的同义词。

**方法：** 先固定应用版本、切片、系统与工具版本，读取对应切片的 `cryptoff/cryptsize/cryptid`；再独立确认可运行、可调试和依赖条件。Frida 的免越狱路径面向可调试应用，文档要求相应 Developer Disk Image 和 Gadget。把“取到元数据”“解密区间可读”“进程启动”“观察到业务调用”分别留证，任何一项缺失都不借其他项补齐。

**版本/边界/反例：** Frida 文档说明自动注入 Gadget 自 12.7.12 起提供，建议 iOS 13 及以上，旧系统支持属实验；这是文档条件，不是本批实测兼容矩阵。单改 cryptid 不会解密字节，零值也不能证明整个应用已具备独立运行条件；商店应用不因具备 IPA 文件就自动可调试。

**方法评审：交叉核对（来源正文已核，已检查适用条件与反例；未做本方目标实测）。** **本方状态：未复现。** 原文来源：[S08：Frida iOS 前提](https://frida.re/docs/ios/)、[S09：Apple Mach-O 加密命令定义](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/EXTERNAL_HEADERS/mach-o/loader.h)。
