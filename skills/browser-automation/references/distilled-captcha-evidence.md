# 验证码：交互证据与服务端结果分层

本篇补充浏览器自动化的验证码观察方法，用于自有或明确授权的测试页面。引入批次：首批全领域增补；引入版本待独立 release PR 分配。目标是定位失败层次，不能从轨迹外观或前端动画推断厂商接受规则。

## DK-CAP-01：滑块和点选先核坐标系与事件流

**现象→判定：** 图像位置判断正确但拖动未生效，首先检查图片像素、页面坐标和实际事件接收者是否一致。Pointer Events 区分 pointerId、pointerType、指针捕获及取消；浏览器还可能合并移动事件，单个 pointermove 不代表一次硬件采样。

**方法：** 在授权页面固定窗口、缩放和布局，记录元素位置、图像显示尺寸及交互开始时的状态。观察 down→move→up/cancel、捕获目标、事件时间和坐标；再将图像中的位置映射到当前页面实际交互区域。逐项改变位置、布局或事件类型，比较控件状态与提交字段，先确认坐标映射和事件到达，再分析图像识别误差。

**版本/边界/反例：** 依据 Pointer Events Level 3；coalesced/predicted events 的实际支持需核浏览器与设备，预测点不等于已经发生的输入。合成事件样例不证明可替代可信硬件事件。失败也可能来自 pointercancel、触摸滚动或捕获迁移；“多加随机点就会通过”没有通用依据，最终停点一致也不代表服务端判断一致。

**验证状态：未验证。** 原文来源：[S15：Pointer Events，捕获、取消与合并事件](https://www.w3.org/TR/pointerevents3/)。

## DK-CAP-02：挑战完成、令牌签发和业务接受分开验证

**现象→判定：** 页面显示完成却提交失败，需区分没有得到令牌、令牌校验失败以及业务拒绝。Google 的 reCAPTCHA 文档规定响应令牌两分钟内有效且只能使用一次；`timeout-or-duplicate` 同时涵盖过期或已经使用，单看错误码不能区分两者。

**方法：** 在自有测试集成中，按顺序记录挑战完成时间、回调、令牌接收与校验时间、服务端校验结果及业务结果。保持私钥只在服务端；公开记录仅保留脱敏标识与错误类别。验证设计至少包含新鲜令牌、过期与重复使用三类对照，分别核验校验端响应和业务是否真正提交，不能只记录前端完成事件。

**版本/边界/反例：** 仅适用于所引 reCAPTCHA 校验接口，不泛化到所有厂商、v3 分数阈值或其他附加策略。刷新页面或重试业务可能复用已消费令牌；再次失败不证明图像识别退化。测试钥匙或测试模式通过，也不证明生产环境风险判断通过；本批没有调用校验接口，未持有或记录任何真实令牌。

**验证状态：未验证。** 原文来源：[S16：reCAPTCHA 响应验证、有效期及错误码](https://developers.google.com/recaptcha/docs/verify)。
