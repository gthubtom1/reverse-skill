# 数字取证：符号身份与时间线可比性

本篇扩充 [取证分诊顺序](forensics-triage.md) 的失败判定，不改变保全优先原则。引入批次：首批全领域增补；引入版本待独立 release PR 分配。原始采集材料、客户主机信息与凭据不得进入公开参考；本批没有读取或调用任何取证镜像。

## DK-DF-01：插件无结果之前先核符号匹配

**现象→判定：** 内存插件报需求不满足、层识别失败或无条目，首先不能下“没有进程/没有注入”的结论。Volatility 3 对 Windows 符号使用 PDB 名称与 GUID/age 匹配；Linux 符号还依赖匹配的内核 banner 和调试信息，单靠发行版名称不够。

**方法：** 先保全镜像摘要，记录采集方式、工具版本、层构建日志和符号来源；区分解析失败、查询成功但为空以及数据已被覆盖。离线环境应预备准确符号并记录缓存身份，不能把联网下载失败视为镜像无效。只有结构解释可信后，才将插件输出与其他独立痕迹交叉核验。

**版本/边界/反例：** 面向 Volatility 3 当前符号文档，不照搬 Volatility 2 的 profile 名称。不同内核配置可能改变结构；拿相近版本的符号强行解析，即使输出格式漂亮，也可能读错偏移。插件成功退出和符号文件存在都不足以证明解释正确；单插件阴性不能排除未覆盖或已丢失的行为。

**验证状态：未验证。** 原文来源：[S22：Volatility 3 符号表与匹配要求](https://volatility3.readthedocs.io/en/latest/symbol-tables.html)。

## DK-DF-02：先统一时间解释，再推断事件顺序

**现象→判定：** 文件时间线与应用日志相差数小时，可能是显示时区、采集端设置或时钟偏差；不能立即认定存在时间戳篡改。mactime 从 body 格式生成活动时间线，输出格式和时区选项有明确交互条件。

**方法：** 保留 body 原文件、生成工具版本及原时间字段，记录来源时区与已知时钟偏差，再生成用于比较的显示结果。每个时间点带上来源和语义，区分文件系统元数据时间、日志记录时间与采集时间；偏差不确定时用时间区间表达，不凭显示顺序断言因果。对关键事件再找独立记录交叉核验。

**版本/边界/反例：** 所引 Sleuth Kit 手册明确 `-z` 指定采集数据时区，名称受系统影响；`-y` 显示 ISO8601，并注明不与 `-z` 配合使用。执行前核安装版本帮助，不把二者机械拼接。单个 mtime 变化既可能来自普通写入也可能被复制/改写，不能独自证明执行或攻击；校正显示时区也不能自动修复主机时钟漂移。

**验证状态：未验证。** 原文来源：[S23：mactime 输入、时区与格式选项](https://www.sleuthkit.org/sleuthkit/man/mactime.html)。
